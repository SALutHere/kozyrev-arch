# Акт 3: Несколько сервисов и транзакции

**Ветка:** `act_3`

## Задача

Руководитель производства просит две вещи:
1. **История операций** - записывать каждое изменение деталей (кто, когда, сколько)
2. **Сборка кораблей** - резервировать детали, собирать корабли, отменять сборку

**Вводные:**
- Начинаем собирать космические корабли из деталей
- При сборке резервируем детали (нельзя использовать для других кораблей)
- При завершении списываем детали окончательно
- При отмене возвращаем детали на склад
- **Ключевое требование:** два менеджера не должны зарезервировать одни и те же детали (атомарность)

**API endpoints:**

Детали:
- `GET /parts` — список деталей
- `POST /parts` — создать деталь
- `POST /parts/{id}/withdraw` — списать детали

Сборка:
- `POST /assembly/start` — начать сборку (резервирует детали)
- `GET /assembly` — список кораблей
- `GET /assembly/{id}` — получить корабль
- `POST /assembly/{id}/complete` — завершить сборку (списать детали)
- `POST /assembly/{id}/cancel` — отменить сборку (вернуть детали)

## Пример использования

```bash
# Начать сборку корабля "Millennium Falcon"
curl -X POST http://localhost:8080/assembly/start \
  -d '{
    "name": "Millennium Falcon",
    "parts": [
      {"part_id": 1, "quantity": 2},
      {"part_id": 2, "quantity": 1},
      {"part_id": 3, "quantity": 10}
    ]
  }'
# → {"id": 1}

# Посмотреть список кораблей в сборке
curl http://localhost:8080/assembly
# → [{"id": 1, "name": "Millennium Falcon", "status": "in_assembly", ...}]

# Получить конкретный корабль
curl http://localhost:8080/assembly/1
# → {"id": 1, "name": "Millennium Falcon", "status": "in_assembly", ...}

# Завершить сборку (списать детали)
curl -X POST http://localhost:8080/assembly/1/complete

# Отменить сборку (вернуть детали)
curl -X POST http://localhost:8080/assembly/1/cancel
```

## Ключевая мысль

> AssemblyService отвечает за корабли. Mutex гарантирует атомарность: проверка + резервирование + создание корабля — одна неделимая операция.

**Статусы корабля:**

```
                    POST /assembly/start
                            │
                            ▼
                  ┌──────────────────┐
                  │  in_assembly     │ ← детали зарезервированы
                  └────────┬─────────┘
                           │
                ┌──────────┴──────────┐
                │                     │
   POST /complete                POST /cancel
                │                     │
                ▼                     ▼
         ┌───────────┐          ┌───────────┐
         │ completed │          │ cancelled │
         └───────────┘          └───────────┘
     детали списаны         детали возвращены
```

**Статусы:**
- `in_assembly` - корабль в сборке, детали зарезервированы
  - **Ручка:** `POST /assembly/start`
  - **Переход:** начальный статус (нет предыдущего)

- `completed` - сборка завершена, детали списаны со склада
  - **Ручка:** `POST /assembly/{id}/complete`
  - **Переход:** из `in_assembly`

- `cancelled` - сборка отменена, детали возвращены на склад
  - **Ручка:** `POST /assembly/{id}/cancel`
  - **Переход:** из `in_assembly`

**Модель детали с резервированием:**

```go
type Part struct {
    Quantity int  // всего на складе
    Reserved int  // зарезервировано для сборки
}

func (p Part) Available() int {
    return p.Quantity - p.Reserved  // доступно для новых резервов
}
```
